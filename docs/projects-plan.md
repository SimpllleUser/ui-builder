# Локальні проєкти: план

## Рішення

| Питання | Рішення |
|---|---|
| Тема, контрольні точки, активна сторінка | свої для кожного проєкту |
| «My components», недавні компоненти, тур, ширини панелей | спільні |
| Import з файлу | створює новий проєкт |
| Undo/Redo | скидається при перемиканні проєкту |
| Classic-редактор | без змін |
| Проєкти, документи, контрольні точки, «My components» | IndexedDB |
| Тема в роботі редактора, налаштування інтерфейсу, id відкритого проєкту | `localStorage` / `sessionStorage` |
| Web Worker | не зараз: клонування для `postMessage` дорожче за серіалізацію. Повернутись, якщо граф, аудит чи експорт дадуть затримку понад 50 мс |

Тема проєкту зберігається разом із ним в IndexedDB. Модуль теми й далі працює зі своїм поточним значенням,
а feature перемикання записує й підставляє його.

Формат документа `Project { pages, layout, state }` і JSON-експорт не змінюються. Назва й дати живуть у `ProjectMeta`.

## Структура

- `shared/lib/indexedDb.ts`: обгортка без бізнес-логіки.
- `modules/projects/entities/project`: репозиторій, назви, міграція. Документ для нього є непрозорим рядком.
- `modules/projects/features/manage-projects`: створити, відкрити, дублювати, видалити, імпортувати.
- `modules/projects/widgets/project-switcher`: UI.

## Етапи

### 1. Репозиторій і міграція
- [x] Асинхронний репозиторій на IndexedDB.
- [x] Міграція з `localStorage` однією транзакцією з позначкою «виконано»; старі ключі не видаляються.
- [x] Тести на `fake-indexeddb`.

### 2. Перемикання у store
- [x] `openProject` у store: незбережене пишеться у свій проєкт, таймери, Preview, виділення та історія скидаються.
- [x] Швидкі повторні перемикання: перемагає останнє.
- [x] Асинхронний запуск з міграцією; редактор і MCP вмикаються після відкриття проєкту.
- [x] Пошкоджений проєкт не відкривається для редагування.
- [x] Запис на `visibilitychange`, попередження `beforeunload`.
- [x] Тема поточного проєкту записується й підставляється (`features/manage-projects`).

### 2б. «My components» в IndexedDB
- Окремий репозиторій у `ui-node` з власною міграцією. Поки що лишаються в `localStorage`.

### 3. Інтерфейс
- [x] Перемикач у верхній панелі та діалог «All projects»: відкрити, перейменувати, дублювати, експортувати, видалити.
- [x] Кількість сторінок рахується з документа під час відкриття списку; пошкоджений проєкт позначений.
- [x] Помилки назви біля поля; видалення з підтвердженням; після видалення останнього створюється порожній.
- [x] Команди в Ctrl/⌘ K; локальний стан панелей скидається через `:key`.
- [ ] Перевірити в браузері.

### 4. Файли
- [x] Експорт `<назва>.json`; Import створює й відкриває новий проєкт; невалідний файл нічого не створює.

### 5. Кілька вкладок
- [x] Відкритий проєкт у `sessionStorage`, для нової вкладки `lastOpenedId`.
- [x] Ревізія документа: запис із застарілої вкладки репозиторій відхиляє.

## Готовність
Наявні дані видно як перший проєкт; проєкти не впливають один на одного; проходять type-check, тести, build,
`format:check`; сценарій перевірено в браузері (міграція, створення, перемикання, перезавантаження, дві вкладки).
