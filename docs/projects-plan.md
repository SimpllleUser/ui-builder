# Локальні проєкти: план

## Рішення

| Питання | Рішення |
|---|---|
| Тема, контрольні точки, активна сторінка | свої для кожного проєкту |
| «My components», недавні компоненти, тур, ширини панелей | спільні |
| Import з файлу | створює новий проєкт |
| Undo/Redo | скидається при перемиканні проєкту |
| Classic-редактор | без змін |
| Проєкти, документи, контрольні точки, «My components» | IndexedDB |
| Тема в роботі редактора, налаштування інтерфейсу, id відкритого проєкту | `localStorage` / `sessionStorage` |
| Web Worker | не зараз: клонування для `postMessage` дорожче за серіалізацію. Повернутись, якщо граф, аудит чи експорт дадуть затримку понад 50 мс |

Тема проєкту зберігається разом із ним в IndexedDB. Модуль теми й далі працює зі своїм поточним значенням,
а feature перемикання записує й підставляє його.

Формат документа `Project { pages, layout, state }` і JSON-експорт не змінюються. Назва й дати живуть у `ProjectMeta`.

## Структура

- `shared/lib/indexedDb.ts`: обгортка без бізнес-логіки.
- `modules/projects/entities/project`: репозиторій, назви, міграція. Документ для нього є непрозорим рядком.
- `modules/projects/features/manage-projects`: створити, відкрити, дублювати, видалити, імпортувати.
- `modules/projects/widgets/project-switcher`: UI.

## Етапи

### 1. Репозиторій і міграція
- [x] Асинхронний репозиторій на IndexedDB.
- [x] Міграція з `localStorage` однією транзакцією з позначкою «виконано»; старі ключі не видаляються.
- [x] Тести на `fake-indexeddb`.

Міграція **ще не викликається**: поки редактор пише в `localStorage`, рання копія застаріла б.
Вона вмикається разом з етапом 2.

### 2. Перемикання у store
- `openProject(id)`: дочекатися запису, скасувати `saveTimer` і `historyTimer`, зупинити Preview, скинути виділення,
  `editingLayout`, `editingPrefabId`, прочитати проєкт, скинути історію (`createHistory().reset()`).
- Швидкі повторні перемикання впорядковуються, застарілий результат не перемагає.
- Асинхронний запуск: редактор показується після завантаження проєкту; тут викликається міграція.
- Пошкоджений проєкт не відкривається для редагування.
- Перенести «My components» в IndexedDB (окремий репозиторій у `ui-node`, з власною міграцією).
- Збереження на `visibilitychange`, попередження `beforeunload`, поки є незбережені зміни.
- Тема поточного проєкту записується й підставляється.

### 3. Інтерфейс
- Перемикач у верхній панелі та діалог «All projects»: відкрити, перейменувати, дублювати, експортувати, видалити.
- Для кількості сторінок у списку додати поле в `ProjectMeta`.
- Помилки назви біля поля; видалення з підтвердженням; після видалення останнього створюється порожній.
- Команди в Ctrl/⌘ K; локальний стан панелей скидається через `:key`.

### 4. Файли
- Експорт `<назва>.json`; Import створює й відкриває новий проєкт; невалідний файл нічого не створює.

### 5. Кілька вкладок
- Відкритий проєкт у `sessionStorage`, для нової вкладки `lastOpenedId`.
- Синхронізація через `BroadcastChannel`; попередження, якщо той самий проєкт змінено деінде.

### 6. MCP і документація
- `list_projects`, `create_project`, `open_project`, `rename_project` (без видалення); проєкт у `get_status`.
- `open_project` і `create_project` заборонені в `batch`; `import_document` і далі замінює поточний проєкт.
- Оновити `mcp/server.mjs`, `mcp/guide.md`, `README.md`.

## Готовність
Наявні дані видно як перший проєкт; проєкти не впливають один на одного; проходять type-check, тести, build,
`format:check`; сценарій перевірено в браузері (міграція, створення, перемикання, перезавантаження, дві вкладки).
